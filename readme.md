# Family Expense Tracker Bot

## Description
A WhatsApp bot that tracks family expenses and stores them in an Excel spreadsheet.
Built by DanielRutman as a learning project to practice Python, pytest, automation, and AWS cloud deployment.

## Medium Article
[From Manual QA to DevOps: How I Built a Production WhatsApp Bot on AWS](https://medium.com/@danielrutman8/from-manual-qa-to-devops-how-i-built-a-production-whatsapp-bot-on-aws-812cb057a665)


## Tech Stack
- Python 3.12
- pytest — automated testing
- openpyxl — Excel integration
- Flask — WhatsApp bot web framework
- Twilio — WhatsApp bot integration
- Locust — load testing
- Selenium — UI testing (does not test the bot itself)
- Docker — containerization
- GitHub Actions — CI/CD pipeline
- Pylint — code quality (score 8.56/10)
- AWS Lambda — serverless deployment (container image)
- AWS API Gateway — HTTP trigger for Lambda
- Amazon ECR — Docker image registry
- AWS CloudWatch — logging
- Amazon S3 — persistent expense data storage

## Architecture
- User sends WhatsApp message → Twilio → API Gateway → Lambda → response back to user
- Infrastructure managed via Terraform
- Monitoring via CloudWatch alarms + SNS email alerts
- Diagrams available in the `diagrams/` folder

## CI/CD Pipeline
Every push to master triggers automatically:
```
Install deps → Pylint ≥ 8.0 → Sanity tests → All tests → Coverage ≥ 90% → E2E → Build + Push to ECR → Deploy to Lambda
```

## AWS Lambda Setup
- Function name: `expense-bot`
- Region: `eu-central-1` (Frankfurt)
- Runtime: Container image (Python 3.12)
- Memory: 256MB | Timeout: 30 seconds
- Handler: `lambda_handler.handler`
- API Gateway URL: generated by Terraform — run `terraform output` to get your URL
- Twilio webhook: same URL as above

## Known Limitations
- **Twilio sandbox** — requires rejoining every 72 hours of inactivity.
  Send `join <your-phrase>` to the Twilio sandbox number on WhatsApp to reconnect.
- **Single region** — deployed to `eu-central-1` (Frankfurt) only.  

## Setup & Installation

### Prerequisites
- Python 3.12
- Docker
- Terraform
- AWS CLI configured
- Twilio account

### Local Development
```bash
# Clone the repo
git clone https://github.com/danielrutman/ExpenseProject.git
cd ExpenseProject

# Create virtual environment
python3 -m venv venv
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Run tests
pytest

# Run bot locally
python expenses_bot.py
```

### Deploy Infrastructure
```bash
cd terraform
terraform init
terraform apply
# Copy the output URL to your Twilio webhook
```

## How To Run Tests
```bash
# Run all tests
pytest

# Run specific suite
pytest -m sanity
pytest -m validation
pytest -m functionality
pytest -m error_handling
pytest -m edge_cases
pytest -m load
pytest -m excel_sanity
pytest -m excel_functionality
pytest -m bot_sanity
pytest -m bot_error_handling
pytest -m bot_functionality

# Run with verbose output
pytest -v

# Generate HTML report
pytest --html=reports/results_report.html --self-contained-html

#Generate HTML test coverage report  into coverage_report folder
pytest --cov=. --cov-report=html:coverage_reports
# to open use below cmd
xdg-open coverage_reports/index.html

# Generate Allure report more  detailed report with charts and more friendly GUI
# Clear old allure data first
rm -rf reports/allure/*
pytest --alluredir=reports/allure
allure serve reports/allure

# Run the WhatsApp bot locally (for local testing only)
# The production bot runs on AWS Lambda

# Terminal 1 - Start Flask
source venv/bin/activate
python expenses_bot.py

# Terminal 2 - Start ngrok tunnel to expose local Flask to Twilio
ngrok http 5000
# Copy the ngrok URL and set it as your Twilio webhook temporarily

# Run Locust load tests
# Terminal 1 - Start Flask
python3 expenses_bot.py
# Terminal 2 - Start Locust
locust -f locustfile.py --host=http://localhost:5000
# Open http://localhost:8089

# Run pylint
pylint $(git ls-files '*.py') --fail-under=8

# Run everything except load tests
pytest -m "not load"

# Run with Docker
docker compose up --build   # build and start
docker compose up -d        # run in background
docker compose down         # stop
docker compose logs         # view logs
docker ps                   # see running containers

```

## Bot Features
- Quick mode — single message format: `name amount category note`
- Guided mode — step by step flow
- Monthly budget tracking — remaining budget shown after each expense
- Session management — 15 minute timeout
- Repeat flow — option to add another expense after saving
- Welcome escape — type "welcome" at any point to return to main menu
- Monthly report — type "report" to see spending per category
